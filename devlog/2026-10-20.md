## Release variant, step 3 build side (17:37-17:55)

User decisions (asked 15:08 after the odex work, answered by 17:36): the release drops
TrebleDroid's su by default and keeps it behind a build option; the first
image without the `/init` wrapper boots only in the clean-install session.

- Kernel-domain denials on zxdbg28 (`device-capture/20261020T0836Z-kernel-avc/`):
  every one comes from the wrapper (busybox, the wrapper shell whose comm is
  `init`, its logcat mirror, `ps.log` on tmpfs). Nothing else leans on the
  permissive `kernel` domain, which stands in for the plan's "boot the debug
  image without it first".
- What the GSI itself ships: `ro.adb.secure=0` (twice in
  `/system/build.prop`, once in `system_ext/etc/build.prop`) and
  `persist.sys.usb.config=adb`, so any computer on the cable gets adb without
  a prompt; `/system/xbin/su` is 04750 root:shell, so that adb shell can
  become root. `ro.debuggable=1` lets adbd restart as root as well.
- TrebleDroid's `phh-securize.sh` was not used: its secure mode also copies
  the vendor fingerprint and spoofs a locked, green verified boot. Its
  `rw-system.sh` (no `set -e`) bind-mounts an empty `su` over `/system/xbin`
  when not secure; with `/system/xbin` gone that mount fails and nothing named
  su is left.
- `make-debug-gsi.sh` split (git mv): `prepare-gsi.sh` grows, unshares and
  adds `BOOTANIM`; `debug-gsi.sh` adds the wrapper, busybox, permissive
  kernel, adb key and `zxdbg.rc`. `release-gsi.sh` sets `ro.adb.secure=1`,
  `persist.sys.usb.config=mtp` and, without `KEEP_SU=1`, `ro.debuggable=0`
  and removes `/system/xbin/su`, `phh-su`, `su.rc`, `/system/xbin`. It
  refuses a debug image and any GSI where a line it changes is missing.
- `build-image.sh`: `RELEASE=1 [KEEP_SU=1]`; debug stays the default. 20
  steps each. The option is not called ROOT: every script uses `ROOT` for the
  repository path, which would have overwritten it.

### vbmeta, as Walkman Manager found it

The app's first update stopped at vbmeta_b: `fastboot: error: Failed to find AVB_MAGIC at
offset: 0`. fastboot 37.0.0 (Fedora's android-tools 37.0.0-4) reads the image looking for an
AVB footer when it is smaller than the partition (`partition-size:vbmeta_b` 0x100000, the
image 4096 bytes), does not seek back, and its `--disable-verity` rewrite then reads nothing.
Nothing was sent. 9bc6ee0: `make-install.sh` sets `AvbVBMetaImageHeader.flags` (big-endian at
120) to 3 itself, byte 123 being the only change (sha256 `4957e2d8…`), and `install.json`
flashes vbmeta_b without flags. The same commit pins `LC_ALL=C.UTF-8`: the Studio's builds
sorted three generated files differently from hand builds. Walkman Manager's update with this
kit then ran through (22:09:55–22:13:41, its devlog).
