# 2026-10-14 a55ui: the A55's UI as an Android app

First milestone (render A55 screens from an APK, no playback), in `apps/a55ui/`.
No device was touched: no adb, fastboot or USB.

## What exists

- Sony `HgrmMediaPlayerApp` QML, unchanged, loaded from a binary resource that
  `scripts/stage.py` packs from the nw-a55 repo's gitignored `work/qrc-device` into
  `apps/a55ui/build/` (gitignored). Fonts, translations and the A55's `/opt2` images
  come from the same place. Nothing from Sony is committed.
- Generated QML stubs for the four global context objects, plus `screens/*.json`
  (values a ViewModel would push) and `qml/Host.qml` (plays FrameWork.qml, scales the
  480-px layout to the display: 1.5x on 720x1280, stage 480x853).
- Screens: Home (library top), Now playing, Settings. Navigation bar, Back and a
  screen picker switch between them; play/pause toggles and the position counts up.
- `build.sh` -> `build/a55ui-arm64-v8a-debug.apk` (32.3 MB, debug-signed v1+v2,
  minSdk 21, targetSdk 28, arm64-v8a only). `render.sh` renders the same QML/stubs on
  host Qt 5.15 in the nw-a55 repo's Docker image. `setup-toolchain.sh` installs Qt
  5.15.2 (aqt), SDK build-tools 28.0.3 + platform 28 + NDK r21e, and Temurin JDK 11
  into `toolchain/`; the APK was rebuilt from that toolchain to prove it.

## Seen working (host only)

Home, player and settings rendered at 720x1280 (and home at 720x1200). Scripted taps:
nav-bar buttons switch screens, Back steps back / opens the picker, picking a screen
loads it, the play button toggles to pause and the time advances (01:02 -> 01:05).

## Not verified

Anything that runs on Android. The APK builds and its contents were inspected
(`aapt dump badging`, `apksigner verify`, NEEDED libs all packaged), but it has not
been installed or launched. Android-only paths: reading `assets:/res/...` with QFile,
registering `stock.rcc` from memory, fonts from data, the Back key, immersive
fullscreen, the Vivante GPU. Quick Controls 1 is forced to the Base style
(`QT_QUICK_CONTROLS_1_STYLE`) so the Android style data is not needed.

## Things learned

- The library-top glyph PNGs (`btn_music_library_filter_*`) are black alpha masks.
  The coloured tile comes from the model's `back_color`; the five colours found in
  the A55 binary (#AED1B3 #B1CFE5 #DDDDDD #FF6757 #FFD2B0) are what `home.json` uses.
  Which tile gets which colour is a guess.
- A55 transport/page-indicator images are `file:/opt2/appresouce/...`; staging
  rewrites them to `qrc:/opt2/appresouce/...` in the staged QML.
- `HeaderArea` with `useVolumeArea: true` shows the quality text, volume bar and the
  battery row (the Player look); with `false` the 28-px volume bar covers the status
  icon row.
- The page-indicator dots belong to swipes only (`preview`), the player's own title
  lives in the meta area (`dispMode: 1`), otherwise the title shows twice.
- `.gitignore` here has `tools/`, which also ignores `apps/a55ui/tools/`; the scripts
  live in `apps/a55ui/scripts/`.

## First device run: SIGSEGV at start-up (fixed)

APK `181d5a1a...` on the ZX507 (Android 13 GSI, arm64, Vivante GC7000, 720x1280): resources,
fonts and the Home screen loaded, then `SIGSEGV (SEGV_MAPERR, 0x58)` in `qtMainLoopThread`,
frame `QQmlIncubatorPrivate::incubate`. The last QML line was `StatusVolumeBar.qml:37:9:
QML Component: Delegate must be of Item type`.

- Not async incubation, not the GPU: reproduced on the host with the toolchain's Qt 5.15.2
  (offscreen platform, software scene graph), same last QML line. gdb: `QQuickRepeater::setModel
  -> requestItems -> QQmlDelegateModel::object -> QQmlIncubatorPrivate::incubate`. Debian's
  Qt 5.15.8 (what render.sh used) only warns, which is why host renders never showed it.
- Cause: `StatusVolumeBar.qml` and `VolumeArea.qml` use `Repeater { model: volumeOperateInfo;
  QtObject {...} }`; my specs supplied that model, so the Repeater instantiated QtObjects.
- Fix (staged copy only): those two Repeaters become `Instantiator` (+ `import QtQml 2.2`),
  which takes non-visual delegates and keeps the volume model working. stage.py asserts
  one hit per file and fails if any other Repeater has a QtObject/Binding/Connections/Timer
  delegate (checked: the regex flags exactly these two in the unpatched tree).
- Also: `extract_android_style` is now `none`. The log showed Qt's ExtractStyle running for
  ~4 s at start and throwing ClassCastException / NoSuchMethodException on Android 13; with
  the Base Quick Controls style forced it is not needed.
- render.sh now builds against Qt 5.15.2 (mounted into the container) instead of the
  container's 5.15.8.
- Verified on the host under Qt 5.15.2: no crash on home, player, settings; a 60-step
  session (tile taps, long-press, page swipe, function icons, transport, scrub, nav, Settings
  scroll and taps, Back/picker) exits 0 and the frames show the interactions took effect.
