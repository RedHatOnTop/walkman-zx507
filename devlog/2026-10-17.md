## Korean tag mojibake: tag-charset, zxdbg19 (14:34-16:54)

Two decoders show tags. MediaStore's comes from libmedia's
`CharacterEncodingDetector` in mediaserver, which decodes every legacy tag of
a file (ID3v1, "ISO-8859-1" frames, UTF-16 that fits in Latin-1) with one
encoding ICU picks for all of them; on this library TagSim's `stock` variant
(`20261017T0453Z-zxdbg18/tagsim.jsonl`) reads 192 CP949 Korean and 25 UTF-8
fields as something else. W.music builds its
own library with Sony's `SpMetaParser`, which decodes legacy frames in the UI
language's charset: CP1252 under en-US, so every CP949 tag is mojibake there
and in the media card.

- mediaserver: `libzx507tagcharset.so` defines
  `CharacterEncodingDetector::detectAndConvert()` ahead of libmedia, as the
  first `DT_NEEDED` of `/system/bin/mediaserver` (`scripts/tag-charset-gsi.sh`).
  `LD_PRELOAD` from the rc (first flash, 15:33:52-15:35:41) is ignored: init's
  transition to mediaserver sets `AT_SECURE`. A patched mediaserver
  bind-mounted from `/data` is refused (`nosuid_transition`). Gated by
  `persist.sys.tagloc=ko` (build.prop).
- Rule (`tag-charset/zx507tagcharset.cpp`, `TagSim.java` identical): CP949
  shape tests per tag, a first pass without Hanja, a second with Hanja once a
  tag of the file passed; valid UTF-8 kept unless it reads as a Latin-letter
  run. Since 16:38 also: a 30-byte value ending in a lone lead byte (ID3v1
  cut) is judged and converted without it, and a single pair inside ASCII
  text is skipped when another tag of the file is Unicode (Wanna One's UTF-16
  "1¹¹=1" had become "1뭐=1"). The unit's `tagcharset-test` harness matches
  TagSim on all 21048 fields, arm and arm64.
- MediaStore rescans (rows marked `_modifier=0`, `content call --method
  scan_volume --arg 3564-3463`, 2 min 15-19 s): after the W3 flash
  (15:51:28-15:53:16) 217 fields changed as TagSim predicted, 13125 stayed,
  all 2563 non-MP3 rows stayed. After the final flash, 16:50:13-16:52:30,
  exactly the two predicted fields changed.
- Gotcha: a root `sqlite3` that closes as the last connection deletes the WAL;
  MediaProvider then fails with `SQLITE_IOERR_SHORT_READ` (15:44) until it is
  restarted. Mark with `.dbconfig no_ckpt_on_close on`.
- W.music: a per-app ko locale (16:01) fixes Korean but empties Western
  Latin-1 ("Beyoncé") and garbles Chinese, so it was reverted.
  `tag-charset/WmTagCharsetFix.java` (dexlib2 + D8) adds
  `tag-charset/ZxTagCharset.java` to `classes5.dex` and hooks `SpMetaParser`
  `setDataSource` / `extractStringData` / `release`. The helper parses again
  with ISO-8859-1, judges the bytes of every tag that fits in Latin-1 (so CP949
  written into UTF-16 frames, 원더걸스, is caught as libmedia catches it),
  converts with `windows-949-2000`, and under CP1252 runs the first pass again
  with Hanja allowed where Hangul is at least as frequent ("사랑의 시(時)").

## microG instead of Google Play services, zxdbg20 (17:14-17:38)

Google Play services is what most store apps expect, and it is heavy;
microG reimplements the parts apps call (accounts, Cloud Messaging, location,
SafetyNet/Play Integrity at basic level at best) in one app.

- `scripts/microg-gsi.sh` on zxdbg19-full: microG Services 0.3.17.252432
  (GmsCore) and microG Companion (`com.android.vending`) as priv-apps,
  GmsCore's six arm64 libraries pre-extracted into `lib/arm64` (they are
  stored compressed, and nothing extracts them for a system app), privileged
  permissions allowlisted from the manifests, `allow-in-power-save` and
  `allow-in-data-usage-save` for GmsCore, and Aurora Store 4.8.4 and F-Droid
  1.23.2 (both from f-droid.org) as plain system apps. APKs pinned by sha256;
  microG's two must be signed with microG's release key (`9bd06727…`).
- Signature spoofing as LineageOS 20 has it (frameworks/base `6d2955f0bd`,
  `53e2f4b85c`): `microg/MicrogSpoofFix.java` (dexlib2 + D8) adds
  `ZxMicrogSpoof` to `services.jar` classes2.dex and calls it before
  `ComputerEngine.generatePackageInfo` returns the installed-package
  PackageInfo. Only gms and vending signed with microG's key whose
  `fake-signature` meta-data is Google's certificate get it, in `signatures`
  and `signingInfo`. No framework-res permission is needed. classes2.dex grows
  by 36 KB; `PhoneWindowManager.interceptKeyBeforeQueueing` (patch-services.py
  nops) disassembles identically.
- Flashed 17:24:07-17:26:05 without a services odex (boot 17:27:33), compiled
  it on the unit with `scripts/services-odex.sh` (17:28:04-17:28:38, key
  `64001ecb526fac2d`), rebuilt and flashed 17:29:07-17:31:04, boot 17:32:27,
  system_server maps `oat/arm64/services.odex`, no crashes. zxdbg20-full sha256
  `38a0d3f2…`.
- `IPackageManager.getPackageInfo(GET_SIGNATURES | GET_SIGNING_CERTIFICATES)`
  from an `app_process` probe: gms and vending report `f0fd6c5b…` (Google) in
  both fields, Aurora `5c83c767…` and F-Droid `43238d51…` their own. microG
  self-check: signature spoofing, both packages and both signatures pass, and
  battery optimizations are ignored. "Services Framework" (GsfProxy, last
  release 2016, a C2DM proxy) is not installed on purpose.
- `default-permissions-microg.xml` (accounts, notifications, phone state for
  GmsCore; notifications for Companion) was not applied on this unit: A13
